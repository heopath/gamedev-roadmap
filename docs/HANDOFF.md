## 3. 사람에 대해 알아야 할 것

작업 결과물을 낼 때 아래를 지켜주세요.

- **쉬운 말로 씁니다.** 전문 용어를 꼭 써야 하면 괄호로 한 번 풀어줍니다.
  (예: "DAW(작곡 프로그램)", "다이어토닉 코드(한 조성에서 쓰는 7개 코드)")
- **포트폴리오 용도라서 잠드는 무료 호스팅은 못 씁니다.** 트래픽이 없으면 멈추는 서비스는 후보에서 제외.
  현재 GitHub Pages를 쓰는 이유가 이것입니다.
- 블로그는 **네이버 블로그**를 씁니다. 스마트에디터가 마크다운을 렌더링하지 않으므로,
  블로그용 원고를 만들 때는 기호를 걷어낸 평문(체크박스는 `☐`)으로 변환해야 합니다.
  현재는 **결과물이 나온 뒤에 올릴 예정**이라 블로그 작업은 보류 상태입니다.

## 4. 파일 구조와 진실의 원천

```
gamedev-roadmap/
├── index.html      ← 진실의 원천. 이것만 고치면 됩니다
├── README.md       ← 같은 내용의 마크다운판 (수동으로 맞춰야 함)
└── docs/HANDOFF.md ← 이 문서
```

`index.html`은 **자체 완결형 단일 파일**입니다. 빌드 도구, 의존성, 패키지 매니저가 없습니다.
외부에서 가져오는 것은 Google Fonts 두 개(Bricolage Grotesque, IBM Plex Sans KR)뿐입니다.

### Claude 아티팩트로 다시 올리는 법

아티팩트는 `<!doctype>`·`<head>`를 자동으로 감싸주기 때문에, `index.html`에서 그 부분을 떼어낸
버전이 필요합니다. **앞 14줄(래퍼)과 뒤 2줄(빈 줄 + `</html>`)을 제거**하면 됩니다:

```bash
sed '1,14d' index.html | head -n -2 > artifact.html
```

결과물의 첫 줄이 `<title>스프라이트와 루프</title>`, 끝 줄이 `</script>`면 정상입니다.
이 파일을 Artifact 도구로 게시하되 **`capabilities: {db: {}}` 를 반드시 함께 선언**해야
동기화가 계속 동작합니다 (선언을 빠뜨리면 조용히 로컬 저장으로 떨어집니다).

### 반대로 Pages용을 만드는 법

`index.html`의 앞 14줄이 그 래퍼입니다. 파일을 새로 만들 일이 생기면 그 14줄을 그대로 앞에 붙이고
끝에 `</html>`을 붙이면 됩니다.

## 5. 깨면 안 되는 규칙

### ⚠️ `data-id`를 바꾸지 마세요

각 체크 항목은 `data-id="p1-7"` 같은 고유 id를 가집니다.
**이 id가 진행 상황 저장의 열쇠입니다.** 바꾸거나 순서를 재배열하면 사용자가 체크해둔 게 전부 날아갑니다.

- 항목을 **추가**할 때: 그 단계의 마지막 번호 다음을 씁니다 (`p1-16` 다음이면 `p1-17`).
  중간에 끼워넣더라도 **번호는 재사용하지 말고 새 번호**를 쓰세요.
- 항목을 **삭제**할 때: 뒤 번호를 당기지 마세요. 구멍이 나도 괜찮습니다.
- 항목 **문구만 고치는 것**은 자유입니다.

현재 배정된 id (총 51개):

| 단계 | id 범위 | 개수 |
| --- | --- | --- |
| 00 세팅 | `p0-1` ~ `p0-5` | 5 |
| 01 픽셀아트 기초 | `p1-1` ~ `p1-16` | 16 |
| 02 첫 출하 | `p2-1` ~ `p2-6` | 6 |
| 03 작곡 기초 | `p3-1` ~ `p3-16` | 16 |
| 04 통합 | `p4-1` ~ `p4-8` | 8 |

### ⚠️ 세 곳의 항목이 항상 같아야 합니다

같은 51개 항목이 **`index.html` / `README.md` / Issue #1** 세 군데에 있습니다.
하나를 고치면 나머지 둘도 고쳐야 합니다. 자동화가 없으니 수동으로 맞춰야 합니다.

작업 후 아래로 확인하세요:

```bash
# 셋 다 같은 숫자가 나와야 합니다
grep -o 'type="checkbox" data-id=' index.html | wc -l
grep -c '^- \[ \]' README.md
gh issue view 1 --repo heopath/gamedev-roadmap --json body -q .body | grep -c '^- \[ \]'

# id 중복이 없어야 합니다 (아무것도 출력되지 않으면 정상)
grep -o 'data-id="[^"]*"' index.html | sort | uniq -d
```

### ⚠️ 단계 상호참조는 "블록 번호"로만 쓰세요

본문에서 다른 단계를 가리킬 때는 **화면에 실제로 보이는 소제목 번호**만 씁니다.
`1-1` `1-2` `1-3` `1-4` `2-1` `3-1` `3-2` `3-3` `3-4` `4-1` `4-2` `0-1` — 이것뿐입니다.

`data-id`(`p3-13` 등)는 화면에 안 보이므로 참조에 쓰면 독자가 찾아갈 수 없습니다.
과거에 이 실수가 5곳 있었고 커밋 `55b3273`에서 고쳤습니다. 반복하지 마세요.

## 6. 동기화가 어떻게 동작하나

한 소스가 두 환경에서 다르게 동작합니다.

| 열린 곳 | 동작 |
| --- | --- |
| Claude 아티팩트 | 계정 저장소에 저장 → 기기 간 동기화 |
| GitHub Pages, 로컬 파일 | 브라우저에만 저장 (localStorage) |

구조:

- 화면은 **항상 localStorage 사본으로 즉시** 그립니다. 네트워크를 기다리지 않습니다.
- 그다음 `window.claude.use("db")`를 시도합니다.
  GitHub Pages에는 `window.claude` 자체가 없으므로 **조용히 건너뜁니다** (에러 아님).
- 붙으면 `progress/checklist` 문서를 구독합니다. 본문은 `{ items: {"p0-1":1, ...}, updatedAt }`.
- 체크하면 로컬 저장 후 **0.4초 뒤 업로드**합니다 (연속 클릭을 한 번으로 묶기 위함).
- 충돌은 **나중에 쓴 쪽이 이깁니다.** 첫 접속 시 서버 문서가 아예 없으면 로컬 것을 올려서 시작합니다.
- 헤더의 점 표시가 현재 상태를 보여줍니다 — 초록 "기기 간 동기화 중" / 회색 "이 브라우저에 저장 중" /
  분홍 "동기화 끊김".

**주의: `db`를 선언하면 아티팩트가 조직 내부용이 되어 공개 공유가 불가능해집니다.**
공개용 링크가 필요하면 GitHub Pages를 쓰세요. 이건 의도된 구성입니다.

## 7. 내용을 쓸 때의 형식

모든 체크 항목은 **접었다 펼 수 있는 "어떻게" 블록**을 하나씩 가집니다. 예외 없습니다.

```html
<li>
  <label><input type="checkbox" data-id="p1-2"><span class="box"></span>
    <span class="txt">항목 제목 — <b>강조</b> <em>· 짧은 부연</em></span></label>
  <details class="how"><summary>어떻게</summary><div class="how-body">
    <ol>
      <li>번호가 매겨진 실행 순서. 3~5개.</li>
    </ol>
    <p class="stuck"><b>막히면</b> 실제로 손이 멈추는 지점에 대한 한 줄.</p>
  </div></details>
</li>
```

내용 원칙:

- **"열심히 하세요" 같은 말은 쓰지 않습니다.** 캔버스 크기, 프레임 타이밍, 메뉴 경로처럼
  **숫자와 구체적 동작**으로 씁니다. ("32×32", "프레임당 120ms", "View → Pixel Grid")
- `막히면`은 **실제로 사람이 멈추는 지점**에만 붙입니다. 모든 항목에 억지로 넣지 마세요.
- 도구를 늘리지 않습니다. 이 로드맵은 **선택지를 줄이는 것**이 핵심 전략입니다.
  "이것도 있고 저것도 있다"는 서술은 이 문서의 목적에 반합니다.

## 9. 왜 그렇게 했나 (결정 기록)

같은 논의를 반복하지 않기 위한 기록입니다.

- **왜 공개 페이지는 동기화가 안 되나** — GitHub Pages는 정적 호스팅이라 서버가 없습니다.
  동기화하려면 별도 백엔드가 필요하고, 공개 페이지의 저장 API는 누구나 호출할 수 있게 됩니다.
  대신 Issue #1이 그 역할을 합니다 (설정 0, 어디서나 동기화).
- **왜 Cloudflare Workers를 안 붙였나** — 무료 한도는 차고 넘칩니다(하루 요청 10만 건, 저장소 쓰기
  1,000회). 기술적 문제가 아니라 **우선순위** 때문에 미뤘습니다. 지금 필요한 건 그림 연습이지
  인프라가 아닙니다. **9~12개월차 "전공으로 메우기" 단계에서 게임 세이브/랭킹 서버로 하기로**
  합의했습니다. 그때는 명분이 생깁니다.
- **왜 진행 상황을 그림 파일과 같은 레포에 안 두나** — 결과물 저장소(`pixel-daily`)는 별도입니다.
  이 레포는 계획만 담습니다.
- **왜 모작을 게임에 쓰지 말라고 적었나** — 저작권. 연습용으로만 쓰고 출처를 적도록 안내합니다.

## 11. 빠른 점검 명령

작업을 마친 뒤 아래를 돌려서 전부 통과하는지 보세요.

```bash
# 항목 수가 셋 다 51인가
grep -o 'type="checkbox" data-id=' index.html | wc -l
grep -c '^- \[ \]' README.md

# id 중복 없는가 (출력 없으면 정상)
grep -o 'data-id="[^"]*"' index.html | sort | uniq -d

# 모든 항목에 "어떻게" 블록이 있는가 (위 개수와 같아야 함)
grep -c '<details class="how">' index.html

# 태그가 닫혔는가 (열림/닫힘 개수가 같아야 함)
for t in section ul li details label; do
  echo "$t: $(grep -o "<$t[ >]" index.html | wc -l) / $(grep -o "</$t>" index.html | wc -l)"
done

# 자바스크립트 문법 확인
awk '/^<script>/{f=1;next} /^<\/script>/{f=0} f' index.html > /tmp/c.js && node --check /tmp/c.js

# 배포 상태
gh api repos/heopath/gamedev-roadmap/pages/builds/latest --jq '{status,sha:.commit[0:7]}'
curl -sS -o /dev/null -w '%{http_code}\n' https://heopath.github.io/gamedev-roadmap/
```
