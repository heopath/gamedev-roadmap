# 스프라이트와 루프

**컴퓨터공학 전공자가 게임에 직접 넣을 그림과 음악을 만들 수 있게 되는 12개월 계획**

목표는 *프로 수준*이 아니라 **게임에 넣어도 부끄럽지 않은 수준**입니다. 하루 30분, 순서대로 하나씩.

> ### 👉 [체크리스트 웹 버전 열기](https://heopath.github.io/gamedev-roadmap/)
> 다음에 할 항목 하나만 크게 보여주고, 항목마다 그날 따라 할 순서가 붙어 있습니다.

진행 상황은 **[Issue #1](https://github.com/heopath/gamedev-roadmap/issues/1)** 에서 체크합니다 — 폰이든 PC든 같은 상태가 보입니다.

아래 각 항목의 **어떻게**를 펼치면 그날 그대로 따라 할 순서가 있습니다.

## 01 · 픽셀아트 기초 — 1~3개월 (주 5회 × 30분)

픽셀아트는 "그림을 잘 그리는" 기술이 아니라 **해상도를 낮춰 난이도를 낮추는** 기법입니다. 32×32 캔버스에서는 손기술보다 판단(형태가 읽히는가, 색을 몇 개 쓸 것인가)이 전부라서, 그림을 못 그려도 몇 주면 쓸 만한 게 나옵니다. **순서를 지키는 것이 중요합니다 — 색부터 손대면 안 늡니다.**

### 📌 참고 · 그릴 때 뭘 보고 그리나

체크 항목이 아니라, 아래 넉 달 내내 옆에 두고 쓰는 방법입니다. 초보가 가장 많이 하는 실수가 처음부터 끝까지 **남의 픽셀아트만** 보는 것입니다. 그러면 그 사람이 내린 판단을 복사할 뿐, 판단하는 법은 늘지 않습니다.

| 단계 | 볼 것 | 왜 |
| --- | --- | --- |
| **1-1 실루엣** | 실제 사진 | 물건의 진짜 형태를 알아야 뭘 버릴지 정할 수 있음 |
| **1-2 명암** | 조명이 뚜렷한 사진 | 빛이 실제로 어떻게 떨어지는지는 사진에만 있음 |
| **1-3 색** | 남의 픽셀아트 | 16색으로 색을 배분하는 법은 픽셀아트에서만 배움 |
| **1-4 애니메이션** | 실사 영상 + 스프라이트 | 움직임은 영상에서, 몇 프레임으로 줄일지는 게임에서 |

1. **사진을 32픽셀로 줄여서 보세요.** 가장 실용적인 요령입니다. 축소하면 픽셀로 옮겼을 때 뭐가 남고 뭐가 사라지는지 그대로 보입니다 — **사라지는 건 안 그려도 되는 것**입니다.
2. **한 장만 보지 마세요.** 같은 물건을 3~4장 띄웁니다. 한 장만 보면 그 사진의 각도와 그림자까지 복사됩니다. 여러 장에서 공통으로 보이는 것이 실루엣으로 남길 것입니다.
3. **Aseprite의 참고 레이어를 쓰세요.** `Layer → New → New Reference Layer…`로 사진을 깔면 내보낼 때 자동으로 빠집니다. 단 **대고 그리는 건 처음 5개까지만** — 계속 대고 그리면 눈이 늘지 않습니다.
4. **눈을 가늘게 뜨고 보세요.** 참고를 볼 때도 똑같습니다. 디테일이 날아가고 남는 덩어리가 그릴 전부입니다.

**찾는 곳** — 사진은 구글 이미지에 `product photo`나 `white background`를 붙여 검색. 픽셀아트는 [Lospec 갤러리](https://lospec.com/gallery)와 [itch.io 무료 에셋 팩](https://itch.io/game-assets/free/tag-pixel-art). 에셋 팩을 하나 받아두면 실제 게임에 들어가는 스프라이트의 밀도가 감으로 잡힙니다.

> **저작권 선** — 연습은 뭘 보고 그려도 자유, 남에게 내놓거나 게임에 넣는 건 직접 그린 것만. 참고를 보는 것 자체에 죄책감을 가질 필요는 없습니다. 프로도 전부 참고를 봅니다. 안 보고 그리는 건 실력이 아니라 기억력이고, 기억은 참고를 수백 번 본 뒤에 생깁니다.

### 1-1 · 실루엣 (2주)

검은 덩어리만으로 뭔지 알아보이게 만드는 단계입니다. 여기서 읽히면 색을 아무리 못 칠해도 살아납니다.

- [ ] 그릴 대상 **20개 목록** 먼저 적어두기

  <details><summary>어떻게</summary>

  1. 메모장에 20개를 그냥 적으세요. 예시 그대로 써도 됩니다 — 검, 방패, 물약, 열쇠, 문, 나무, 버섯, 보물상자, 횃불, 사다리, 항아리, 두루마리, 반지, 활, 도끼, 왕관, 책, 폭탄, 물고기, 별.
  2. 고를 때 기준은 하나: **실루엣이 특징적인 것**. 구름·물 같은 건 나중에.
  3. 레포에 `2026-09/list.txt`로 커밋해두고, 매일 위에서부터 하나씩 지워나갑니다.

  </details>

- [ ] 32×32에 **단색 실루엣 20개** — 하루 2개씩 10일

  <details><summary>어떻게</summary>

  1. 팔레트에서 **검정 한 색만** 선택. 다른 색은 오늘 쓰지 않습니다.
  2. 대상마다 **가장 알아보기 쉬운 각도**를 먼저 정하기 — 검은 옆에서, 왕관은 정면에서, 열쇠는 비스듬히.
  3. 연필로 외곽선부터 긋지 말고, **사각형 덩어리**를 크게 놓은 다음 지우개로 깎아내세요. 조각하듯이.
  4. 한 개에 **최대 5분**. 타이머 울리면 미완성이어도 저장하고 다음 것으로.
  5. 매일 끝나면 그날 것 커밋.

  > **막히면** — 형태가 애매하면 실제 사진을 찾아 **눈을 가늘게 뜨고** 덩어리만 보세요. 디테일이 아니라 윤곽이 전부입니다.

  </details>

- [ ] 5개 골라 **남에게 맞혀보게 하기** — 3개 이상 맞으면 통과

  <details><summary>어떻게</summary>

  1. 실루엣 5개를 한 장에 나란히 배치해 PNG로 내보내기 (배율 400%로 키워서).
  2. 친구나 가족에게 보내고 **"이거 뭐로 보여?"** 만 물어보세요. 힌트·주제·맥락 전부 금지.
  3. 맞힌 개수를 메모에 기록. 3개 미만이면 실루엣 5개를 더 그리고 다시 테스트.

  > **막히면** — 안 맞히는 건 색을 안 칠해서가 아닙니다. 형태 선택이 틀린 겁니다. 각도를 바꿔 다시 그리세요.

  </details>

- [ ] 잘 안 읽힌 것 3개 **외곽선만 고쳐서** 다시 그리기

  <details><summary>어떻게</summary>

  1. 원본 파일을 복사해서 `-v2`로 새로 만들기. 원본은 지우지 마세요 — 비교가 남아야 합니다.
  2. 고칠 건 딱 두 가지: **비율**(부분이 너무 작거나 큼)과 **튀어나온 특징**(칼자루 가드, 왕관 뿔 등).
  3. v1과 v2를 나란히 놓고 PNG 한 장으로 저장. 이게 첫 성장 기록입니다.

  </details>

### 1-2 · 명암 (3주)

그림이 안 예뻐 보이는 이유의 대부분은 색이 아니라 명암입니다. 색은 아직 쓰지 않습니다.

- [ ] **흑백 3단계**로만 아이템 20개

  <details><summary>어떻게</summary>

  1. 팔레트를 직접 3칸으로 만드세요: `#2b2b2b`, `#7a7a7a`, `#e0e0e0`. 이 3색 외엔 쓰지 않습니다.
  2. 1-1에서 그린 실루엣을 재활용하세요. 새로 그리지 말고 **덩어리 안을 나누는 연습**입니다.
  3. 순서: 전체를 중간색으로 채움 → 빛 받는 면을 밝음으로 → 그림자 면을 어두움으로.
  4. 하루 2개, 10일.

  > **막히면** — 3단계가 답답해도 늘리지 마세요. 색 수를 늘리면 판단이 흐려져서 오히려 안 늡니다.

  </details>

- [ ] 광원 방향 **왼쪽 위로 고정**하고 20개 내내 지키기

  <details><summary>어떻게</summary>

  1. 캔버스 왼쪽 위 구석에 작은 점 하나를 찍어두고 작업하세요. 다 그리면 지웁니다. 광원을 잊지 않기 위한 표식입니다.
  2. 규칙 두 개만: **왼쪽 위 면은 밝음**, **오른쪽 아래 면은 어두움**.
  3. 다 그린 뒤 20개를 한 화면에 모아 보세요. 광원이 흔들린 게 바로 보입니다.

  > **막히면** — 게임 스프라이트가 대부분 왼쪽 위 광원인 이유는, 여러 사람이 그려도 한 세트로 보이게 하기 위해서입니다. 취향이 아니라 규약입니다.

  </details>

- [ ] 매번 **눈 가늘게 뜨고** 형태가 남는지 확인하기

  <details><summary>어떻게</summary>

  1. 완성했다 싶으면 화면에서 **한 발 물러나 눈을 가늘게** 뜹니다. 또는 배율을 100%로 줄여서 보세요.
  2. 덩어리가 뭉개져 하나로 보이면 **명암 대비가 부족**한 것 — 밝음을 더 밝게, 어두움을 더 어둡게.
  3. 매 작업 끝에 이 확인을 하고, 고친 것은 파일명에 `-fix`를 붙여 남기세요.

  </details>

- [ ] 부족했던 5개를 **4단계**로 다시 그려 비교

  <details><summary>어떻게</summary>

  1. 3색 팔레트에 **하이라이트 한 칸**을 추가합니다 (`#ffffff`에 가까운 색).
  2. 하이라이트는 **가장 튀어나온 한 지점에만**. 넓게 칠하면 즉시 싸구려로 보입니다.
  3. 3단계 버전과 4단계 버전을 나란히 저장해서 커밋.

  </details>

  <details><summary>어떻게</summary>

  1. Sweetie 16을 불러오고, **스포이드로 팔레트에서만** 색을 집으세요. 색상환에서 직접 고르는 건 금지.
  2. 1-2에서 만든 흑백 그림을 색으로 옮기는 연습입니다. **명암 단계는 그대로 두고 색만 갈아 끼우세요.**
  3. 어두운 부분은 단순히 검정을 섞지 말고, **팔레트에서 더 어둡고 채도 있는 색**을 고르세요 (예: 갈색의 그림자는 회색이 아니라 보라·남색 쪽).
  4. 하루 2개, 10일.

  > **막히면** — 그림자에 "같은 색의 어두운 버전"만 쓰면 탁해 보입니다. 그림자는 색상(hue)을 살짝 파란·보라 쪽으로 돌리는 게 정석입니다.

  </details>

- [ ] 같은 스프라이트를 **팔레트 3개로** 각각 칠해보기

  <details><summary>어떻게</summary>

  1. 가장 잘 나온 스프라이트 하나를 고릅니다.
  2. 레이어를 복제해서 Sweetie 16 / PICO-8 / Endesga 32 버전을 각각 만들기.
  3. 세 개를 나란히 놓고 PNG 한 장으로 저장 — **같은 형태가 팔레트만으로 얼마나 달라지는지**가 이 연습의 전부입니다.

  </details>

- [ ] 색 **5개 이하**로 제한한 32×32 캐릭터 1개

  <details><summary>어떻게</summary>

  1. 32×32 안에서 캐릭터는 대략 **가로 16 · 세로 24** 정도를 차지하게 잡으세요. 꽉 채우면 애니메이션할 여백이 없습니다.
  2. 색 배분: 피부 1 · 옷 2(밝음/어두움) · 머리 1 · 외곽선 1. 이걸로 5개입니다.
  3. 얼굴 디테일은 **눈 두 점**이면 충분합니다. 32px에서 코와 입은 넣을수록 나빠집니다.
  4. 완성하면 배율 100%로 축소해서 확인 — 이 크기에서 사람으로 보이면 성공.

  > **막히면** — 이 캐릭터를 1-4 애니메이션과 게임잼까지 계속 씁니다. 마음에 드는 걸로 만드세요.

  </details>

- [ ] 같은 캐릭터의 **낮 / 밤 버전** — 팔레트만 바꿔서

  <details><summary>어떻게</summary>

  1. 밤 버전은 전체적으로 **어둡게** + **파란 쪽으로** + **대비를 줄여서**.
  2. 색을 하나하나 다시 고르지 말고, 팔레트에서 각 색의 "밤 대응 색"을 정해 표를 만들어 교체하세요.
  3. 이 색 대응표가 나중에 4-1의 **팔레트 스왑 스크립트**가 됩니다. 표를 버리지 마세요.

  </details>

### 1-4 · 애니메이션 (4주)

여기까지 오면 게임 하나를 만들 수 있습니다. 프레임 수를 늘리지 말고, 적은 프레임으로 읽히게 하세요.

- [ ] **4프레임 코인 회전**

  <details><summary>어떻게</summary>

  1. 16×16 캔버스, 프레임 4개 (Aseprite에서 `Alt+N`으로 프레임 추가).
  2. 1번: 정면 원. 2번: 살짝 납작한 타원. 3번: **세로 선 한 줄**(옆면). 4번: 다시 타원.
  3. 재생 속도는 프레임당 **100ms**부터. 스페이스바로 미리보기.
  4. GIF로 내보내서 커밋 (`Ctrl+Alt+Shift+S` → gif).

  > **막히면** — 3번 프레임을 과감하게 얇게 만들어야 회전으로 보입니다. 어중간하면 그냥 찌그러진 원으로 보입니다.

  </details>

- [ ] **6프레임 걷기 사이클** — 1-3에서 만든 캐릭터로

  <details><summary>어떻게</summary>

  1. 순서를 이렇게 잡으세요: **접촉 → 낮은 지점 → 통과 → 접촉(반대발) → 낮은 지점 → 통과**.
  2. 제일 먼저 그릴 건 **1번(접촉)과 4번(반대발 접촉)** 입니다. 두 개가 대칭이면 나머지는 쉽습니다.
  3. 몸통 전체를 **1픽셀 위아래로** 움직이세요. 이 상하 운동이 걷기의 90%입니다.
  4. 프레임당 120ms로 재생하고, 제자리 걸음이 어색하지 않으면 완성.

  > **막히면** — 팔다리를 정교하게 그리려 하지 마세요. 32px에서 다리는 2~3픽셀 폭입니다. 위치만 바뀌면 뇌가 알아서 걷는 걸로 봅니다.

  </details>

- [ ] **8프레임 공격 모션** — 예비동작 3 + 타격 1 + 잔상 4

  <details><summary>어떻게</summary>

  1. 1~3번은 **뒤로 젖히는** 예비동작. 천천히(프레임당 120ms).
  2. 4번은 **타격 한 장**. 여기만 60ms로 짧게 — 빠를수록 세게 느껴집니다.
  3. 5~8번은 무기 궤적(흰 반달)과 원위치 복귀.
  4. 타격 프레임에서 캐릭터를 **1~2픽셀 앞으로** 밀어보세요. 타격감이 확 달라집니다.

  > **막히면** — 타격감은 그림이 아니라 **타이밍**에서 나옵니다. 예비동작을 길게, 타격을 짧게. 이 비율만 지키면 됩니다.

  </details>

- [ ] **모작 30개** — 좋아하는 게임 스프라이트를 그대로 따라 찍기

  <details><summary>어떻게</summary>

  1. The Spriters Resource 같은 곳에서 좋아하는 게임의 스프라이트 시트를 구해 **참고용으로만** 옆에 띄웁니다.
  2. 복사·붙여넣기 금지. **보고 한 픽셀씩 다시 찍으세요.** 그 과정에서 "왜 여기에 이 색을 썼는지"가 보입니다.
  3. 하나 끝날 때마다 **한 줄 메모**: 배운 점 하나. 예 — "외곽선을 검정이 아니라 어두운 갈색으로 썼다".
  4. 1-1부터 1-4까지 진행하면서 **병행**하세요. 하루 30분 중 10분을 모작에 쓰면 3개월에 30개가 됩니다.
  5. 모작은 연습용입니다. 공개 레포에 올릴 땐 **출처를 적고**, 게임에 쓰지는 마세요.

  > **막히면** — 이 항목 하나가 나머지 전부보다 효과가 큽니다. 다른 걸 빼먹더라도 모작은 채우세요.

  </details>

> **완료 기준** — 게임에 바로 넣을 수 있는 캐릭터 1종 + 대기·걷기·공격 애니메이션, 그리고 모작 30개.

## 02 · 첫 출하 — 4개월차 (게임잼)

이 단계가 로드맵 전체에서 가장 중요합니다. "48시간 안에 어떻게든 끝내야 하는" 압박이 완벽주의를 없애주고, 무엇보다 **실제로 게임에 들어간 결과물**이 남습니다. 음악은 아직 무료 에셋을 써도 됩니다 — 이번엔 그림만 직접.

- [ ] 잼 일정 확인하고 **캘린더에 등록**

  <details><summary>어떻게</summary>

  1. [Ludum Dare](https://ldjam.com/)(연 2회, 48/72시간)와 [itch.io 잼 목록](https://itch.io/jams)에서 **4개월차에 걸리는 것**을 하나 고르세요.
  2. 날짜를 캘린더에 **이틀 통째로** 잡고, 그 주말 약속을 미리 비웁니다.
  3. 규모가 부담되면 itch.io의 소규모 잼(참가자 수십 명)으로 시작해도 효과는 같습니다.

  </details>

- [ ] 잼 전에 **혼자 48시간 미니잼** 1회 연습

  <details><summary>어떻게</summary>

  1. 주제는 아무 단어나 하나 뽑으세요. "중력", "열쇠", "밤" 같은 것.
  2. 목표는 재미가 아니라 **완주**입니다. 화면 하나, 조작 하나, 끝나는 조건 하나면 충분합니다.
  3. 시간을 미리 쪼개두세요: **기획 2h → 코드 20h → 아트 12h → 사운드 4h → 마무리·업로드 10h**.
  4. 끝나면 실제 itch.io에 올려서 **업로드까지** 해보세요. 본 대회 때 여기서 시간을 안 뺏깁니다.

  > **막히면** — 미니잼에서 못 끝냈다면 본 대회 계획을 반으로 줄이세요. 규모를 줄이는 건 실패가 아니라 유일하게 통하는 전략입니다.

  </details>

- [ ] 잼 참가 — **아트는 100% 직접**, 음악은 무료 에셋 허용

  <details><summary>어떻게</summary>

  1. 시작 전에 **스프라이트 목록을 먼저** 적으세요. 캐릭터 1 · 적 1 · 타일 3 · 아이템 2 정도로 상한을 두고, 그 이상은 안 만듭니다.
  2. 1-3에서 만든 캐릭터를 그대로 쓰세요. 새로 만들 시간 없습니다.
  3. 음악은 [itch.io 무료 음악 에셋](https://itch.io/game-assets/free/tag-music)에서. 라이선스(CC0 / CC-BY)를 확인하고 **크레딧을 적어두세요.**
  4. 마지막 4시간은 **무조건** 버그 수정과 업로드용으로 비워둡니다.

  > **막히면** — 잼에서 미완성으로 끝나는 1번 원인은 아트를 너무 많이 계획한 것입니다. 목록에 상한을 두세요.

  </details>

- [ ] **itch.io 페이지** 만들고 스크린샷 3장 + GIF 1개 올리기

  3. 설명은 세 줄이면 충분: 뭘 하는 게임인지 / 조작키 / 크레딧(쓴 음악 에셋 출처).
  4. 웹(HTML5)으로 빌드할 수 있으면 반드시 웹으로. 다운로드는 사람들이 안 받습니다.

  </details>

- [ ] 회고 **5줄** 쓰기

  <details><summary>어떻게</summary>

  1. 레포에 `retro-2027-01.md` 같은 파일로 남기세요.
  2. 다섯 줄만 채웁니다 — 가장 오래 걸린 것 / 가장 부족했던 것 / 다시 쓸 수 있게 만들어둘 것 / 다음에 안 할 것 / 의외로 잘 된 것.

## 03 · 작곡 기초 — 5~8개월 (주 5회 × 30분)

여기서 전공이 유리해집니다. **음악 이론은 사실상 정수 연산입니다** — 음정은 반음 개수, 스케일은 12칸 배열의 패턴, 코드 진행은 상태 전이입니다. 이걸 규칙으로 이해하면 "감"으로 배우는 것보다 훨씬 빠릅니다.

### 3-1 · 세팅 (1주)

- [ ] **DAW 설치** — REAPER 또는 LMMS

  <details><summary>어떻게</summary>

  1. [REAPER](https://www.reaper.fm/)를 받으세요. 평가판이 기능 제한 없이 계속 실행되고, 마음에 들면 개인 라이선스가 $60입니다. 완전 무료를 원하면 [LMMS](https://lmms.io/).
  2. 설치 후 **Options → Preferences → Audio → Device**에서 출력 장치를 잡고 소리가 나는지 확인.
  3. 새 프로젝트 템포는 일단 `120 BPM`, 박자는 `4/4`로 두세요.
  4. 트랙 하나 만들고(`Ctrl+T`) MIDI 아이템을 그려 아무 음이나 재생해보기.

  > **막히면** — 소리가 안 나면 십중팔구 오디오 드라이버 문제입니다. Windows라면 장치를 **WASAPI**로 바꿔보세요.

  </details>

- [ ] **무료 음원** 설치 — LABS, Vital, Surge XT

  <details><summary>어떻게</summary>

  1. [Spitfire LABS](https://labs.spitfireaudio.com/) — 실제 악기 소리. 일단 **Soft Piano**와 **Strings**만 받으세요.
  2. [Vital](https://vital.audio/) — 신디사이저. 게임 음악의 리드·베이스는 대부분 여기서 나옵니다.
  3. [Surge XT](https://surge-synthesizer.github.io/) — 무료인데 프리셋이 많아 고르기만 해도 됩니다.
  4. 설치 후 DAW에서 **플러그인 폴더를 다시 스캔**해야 목록에 뜹니다 (REAPER: Preferences → Plug-ins → VST → Re-scan).

  > **막히면** — 음원을 더 모으지 마세요. 이 셋으로 12개월 내내 충분합니다. 음원 수집은 미루기의 다른 형태입니다.

  </details>

- [ ] (선택) **25건반 MIDI 키보드**

  <details><summary>어떻게</summary>

  1. 2~3만 원대 25건반이면 충분합니다. 건반 수나 터치감은 지금 단계에서 의미 없습니다.
  2. USB로 연결하면 대부분 드라이버 없이 잡힙니다.
  3. 키보드가 있으면 좋은 이유는 연주가 아니라 **코드를 손으로 눌러보며 귀로 확인**할 수 있어서입니다.

  </details>

- [ ] 아무 소리나 넣고 **파일 내보내기까지** 한 번 성공

  <details><summary>어떻게</summary>

  1. 트랙에 4마디짜리 아무 음이나 찍습니다.
  2. 내보낼 구간을 선택 (REAPER: 타임라인에서 드래그해 Time Selection 만들기).
  3. **File → Render** → Bounds를 `Time selection`, 포맷은 `WAV` 또는 `MP3` → Render.
  4. 나온 파일을 실제로 플레이어로 열어서 소리가 나는지 확인하세요.

  > **막히면** — 빈 파일이 나오면 대개 Time selection이 없거나 트랙이 뮤트 상태입니다. 이 두 가지부터 확인하세요.

  </details>

### 3-2 · 리듬 (3주)

멜로디부터 시작하면 십중팔구 막힙니다. 드럼이 곡의 뼈대입니다.

- [ ] 킥·스네어·하이햇만으로 **8마디 드럼 루프 10개**

  <details><summary>어떻게</summary>

  1. 기본형부터: **킥은 1박과 3박, 스네어는 2박과 4박, 하이햇은 8분음표로 계속.** 이게 대부분 게임 음악의 뼈대입니다.
  2. 기본형을 만든 뒤 **한 번에 하나씩만** 바꾸세요 — 킥을 한 개 더 넣기, 하이햇을 16분으로, 스네어를 한 박 밀기.
  3. 10개를 각각 다른 파일로 저장. 나중에 곡의 시작점으로 재활용합니다.
  4. 하루 1개, 10일.

  > **막히면** — 드럼이 심심하게 느껴져도 채우지 마세요. 게임 BGM은 몇 시간을 반복해 들어야 해서, 화려한 드럼이 오히려 금방 질립니다.

  </details>

- [ ] 좋아하는 게임 BGM **3곡의 드럼만** 귀로 따서 재현

  <details><summary>어떻게</summary>

  1. 곡을 DAW에 오디오로 불러오고 그 위에 트랙을 얹어 맞춰 찍으세요.
  2. 먼저 **템포를 맞추는 것**부터. 킥이 그리드에 딱 붙으면 성공입니다.
  3. 킥 → 스네어 → 하이햇 순으로 하나씩. 한 번에 다 들으려 하지 말고 **한 악기만 골라 듣기.**
  4. 못 딴 부분은 비워두고 넘어가세요. 정확도가 아니라 귀 훈련이 목적입니다.

  </details>

- [ ] 같은 패턴을 **템포 3가지**로 듣고 차이 기록

  <details><summary>어떻게</summary>

  1. 드럼 루프 하나를 `80 / 120 / 160 BPM`으로 재생해보세요.
  2. 메모에 각각의 인상을 한 줄씩: "80은 무겁고 던전, 120은 평범한 마을, 160은 쫓기는 느낌".
  3. 이 표가 나중에 **어떤 장면에 어떤 템포를 쓸지**의 기준이 됩니다.

  </details>

### 3-3 · 코드 (4주)

한 조성에서 쓰는 7개 코드(다이어토닉 코드)만 알면 게임 음악의 대부분이 설명됩니다.

- [ ] **다이어토닉 7코드** 외우기 — C조 기준 `C · Dm · Em · F · G · Am · Bdim`

  <details><summary>어떻게</summary>

  1. 규칙만 알면 외울 게 없습니다. 메이저 스케일은 반음 간격이 `2-2-1-2-2-2-1`이고, 각 음 위에 **한 칸 건너뛰며 3개**를 쌓으면 그 조의 7코드가 나옵니다.
  2. 결과는 항상 같은 패턴입니다: **메이저 · 마이너 · 마이너 · 메이저 · 메이저 · 마이너 · 디미니시드**. 조가 바뀌어도 이 순서는 안 바뀝니다.
  3. DAW에서 C조 7코드를 전부 찍어놓고 한 번씩 들어보세요. 밝은 코드와 어두운 코드가 귀로 구분되면 됩니다.
  4. 전공을 살리고 싶다면 이 패턴을 만드는 함수를 20줄쯤 짜보세요. 코드로 이해하면 안 잊습니다.

  </details>

- [ ] **Hooktheory**에서 게임 BGM 10곡 진행 확인하고 패턴 적기

  <details><summary>어떻게</summary>

  1. [TheoryTab](https://www.hooktheory.com/theorytab)에서 아는 게임 곡을 검색하세요. 코드 진행이 숫자로 표시됩니다.
  2. 10곡의 진행을 메모에 나열하고, **반복되는 것**을 표시하세요. `I–V–vi–IV`, `vi–IV–I–V` 같은 게 계속 나올 겁니다.
  3. 이 목록이 앞으로 쓸 재료입니다. 새로 발명하지 말고 **여기서 골라 쓰세요.**

  </details>

- [ ] **4코드 루프 20개** 만들기 — 멜로디 없이 코드만

  <details><summary>어떻게</summary>

  1. 한 루프는 4마디, 코드 하나에 한 마디씩.
  2. 앞서 정리한 진행 목록에서 골라 쓰되, **20개 중 절반은 그대로, 절반은 코드 하나만 바꿔서** 만드세요.
  3. 악기는 피아노 하나로 고정. 음색을 고르는 데 시간을 쓰지 마세요.
  4. 하루 2개, 10일.

  > **막히면** — 코드를 세 음 그대로 나란히 찍으면 딱딱하게 들립니다. 가운데 음을 한 옥타브 올리거나(자리바꿈) 베이스만 따로 빼면 훨씬 나아집니다.

  </details>

- [ ] 같은 진행을 **메이저 / 마이너**로 바꿔 각각 저장

  <details><summary>어떻게</summary>

  1. 가장 마음에 드는 루프 3개를 고릅니다.
  2. 같은 자리의 코드를 **나란한 단조**로 옮기세요 (C조 → Am조). 음은 그대로 두고 시작 코드만 바꿔도 분위기가 뒤집힙니다.
  3. 메이저·마이너 버전을 같은 이름 `-major` / `-minor`로 저장. 이게 3-4의 레이어링 재료가 됩니다.

  </details>

### 3-4 · 멜로디와 루프 (6주)

루프 이음새와 레이어링은 일반 작곡 강의에 잘 안 나오는데, 게임 음악에서는 이게 핵심입니다.

- [ ] 코드 루프 위에 **멜로디 얹기 10개**

  <details><summary>어떻게</summary>

  1. 규칙 하나만: **각 마디의 첫 음은 그 마디 코드에 들어 있는 음**으로. 나머지는 비교적 자유롭습니다.
  2. 음을 촘촘히 채우지 말고 **쉼표를 넣으세요.** 초보 멜로디가 답답한 건 대개 쉬지 않아서입니다.
  3. 4마디를 만들고 **그대로 한 번 반복**하되 마지막 두 음만 바꾸세요. 그게 8마디 멜로디입니다.
  4. 하루 1개, 10일.

  </details>

- [ ] **30초 BGM 완성 5곡** — 완성은 내보내기까지

  <details><summary>어떻게</summary>

  1. 구성은 이렇게 고정하세요: **드럼 + 베이스 + 코드 + 멜로디**, 네 트랙.
  2. 베이스는 각 마디 코드의 **가장 낮은 음 하나**만 길게. 이것만으로 곡이 훨씬 단단해집니다.
  3. 볼륨 순서: 드럼과 베이스를 크게, 코드를 작게, 멜로디를 그 중간. 코드가 크면 탁해집니다.
  4. WAV로 내보내서 레포에 커밋. 미완성이어도 내보낸 것만 셉니다.

  > **막히면** — 곡이 심심하면 악기를 더하지 말고 **빼세요.** 게임 BGM은 화면 뒤에 깔리는 소리라 비어 있는 편이 낫습니다.

  </details>

- [ ] **루프 이음새** 다듬기 — 끝에서 처음으로 돌아갈 때 티 안 나게

  <details><summary>어떻게</summary>

  1. 마지막 마디의 코드를 **V(도미넌트)** 로 두면 첫 코드로 자연스럽게 이어집니다.
  2. 내보낼 때 **정확히 마디 경계에서** 자르세요. 반 박자만 어긋나도 반복할 때 걸리는 느낌이 납니다.
  3. 리버브 꼬리가 잘리면 뚝 끊깁니다. 곡 끝에서 리버브를 줄이거나, 꼬리를 곡 앞부분에 겹쳐 넣으세요.
  4. 실제로 **5번 이상 반복 재생**해서 확인. 한 번 들어서는 안 들립니다.

  </details>

- [ ] **레이어링** — 같은 곡의 "평상시 / 전투" 두 버전

  <details><summary>어떻게</summary>

  1. 30초 BGM 중 하나를 고르고, **트랙 구성은 그대로** 둡니다.
  2. 평상시 버전: 드럼과 리드를 **끔**. 코드와 베이스만.
  3. 전투 버전: 전부 **켬**. 여기서 음을 새로 쓰지 마세요 — 켜고 끄는 것만으로 만드는 게 요령입니다.
  4. 두 버전을 같은 길이·같은 템포로 내보내면, 게임에서 **재생 위치를 유지한 채** 교체할 수 있습니다. 이게 4-1의 오디오 매니저가 하는 일입니다.

  > **막히면** — 두 파일의 길이가 1샘플이라도 다르면 전환할 때 어긋납니다. 반드시 같은 구간을 내보내세요.

  </details>

- [ ] 게임 BGM **3곡 모작** — 귀로 듣고 MIDI로 재현

  <details><summary>어떻게</summary>

  1. 구조가 단순한 곡을 고르세요. 8비트·16비트 시대 곡이 배우기 좋습니다.
  2. 순서: 드럼 → 베이스 → 코드 → 멜로디. **베이스를 먼저 따면** 코드가 저절로 보입니다.
  3. 딴 뒤에 [8-bit Music Theory](https://www.youtube.com/@8bitMusicTheory)에 그 곡 분석 영상이 있는지 찾아보세요. 내 귀와 남의 분석을 대조하는 게 가장 빠른 학습입니다.
  4. 모작은 연습용입니다. 게임에 쓰지 마세요.

  </details>

> **완료 기준** — 게임에 넣어도 되는 30초~1분 루프 BGM 3곡, 그리고 레이어 분기 버전 1곡.

## 04 · 통합, 그리고 전공 살리기 — 9~12개월

여기서부터는 손기술이 아니라 코드로 격차를 메웁니다. 단순한 스프라이트 하나도 셰이더로 아웃라인·피격 플래시를 넣으면 화면이 훨씬 좋아 보입니다. 그림을 더 잘 그리는 것보다 **이쪽이 투자 대비 효과가 큽니다.**

### 4-1 · 전공으로 메우기

- [ ] **셰이더 1개** — 피격 플래시 또는 아웃라인

  <details><summary>어떻게</summary>

  1. **피격 플래시**부터 하세요. 프래그먼트 셰이더에서 원래 색을 흰색과 섞고, 그 섞는 비율을 스크립트에서 0.1초 동안 1 → 0으로 되돌리면 끝입니다. 10줄이면 됩니다.
  2. **아웃라인**은 그다음. 각 픽셀에서 상하좌우 네 칸을 샘플링해, 자기가 투명한데 이웃이 불투명하면 외곽선 색을 칠합니다.
  3. 엔진마다 문법이 다르니 쓰는 엔진 이름 + `sprite flash shader`로 검색하세요. 개념은 위 두 줄이 전부입니다.
  4. 적용 전/후 GIF를 나란히 찍어두세요. 4-2 블로그 글에서 가장 반응이 좋은 자료가 됩니다.

  > **막히면** — 피격 플래시 하나만으로도 화면 인상이 눈에 띄게 달라집니다. 여기서 그만둬도 본전은 뽑습니다.

  </details>

- [ ] **오디오 매니저** — 상황에 따라 트랙을 켜고 끄며 곡 분기

  <details><summary>어떻게</summary>

  1. 3-4에서 만든 두 버전을 **동시에 재생**하되, 한쪽 볼륨을 0으로 두는 방식이 가장 간단합니다. 재생 위치가 저절로 맞습니다.
  2. 전환은 즉시 바꾸지 말고 **0.5초에 걸쳐 볼륨을 교차**시키세요. 뚝 끊기면 싸구려로 들립니다.
  3. API는 세 개면 충분합니다: `play(track)` · `setLayer(name, on)` · `fadeTo(state, seconds)`.
  4. 전투 진입/이탈에 붙여서 실제로 동작하는지 확인.

  </details>

- [ ] **팔레트 스왑 스크립트** — 색만 바꿔 적 캐릭터 변형 생성

  <details><summary>어떻게</summary>

  1. 1-3에서 만들어둔 **색 대응표**를 JSON으로 옮기세요. `{"#a05030": "#3050a0", ...}` 형태면 됩니다.
  2. PNG를 읽어 픽셀을 순회하며 표에 있는 색을 치환하고 저장하는 스크립트 — 파이썬 `Pillow`로 30줄이면 끝납니다.
  3. 스프라이트 1종 × 팔레트 4개 = 적 4종. **이게 픽셀아트에서 전공자가 가장 크게 이기는 지점입니다.**
  4. 런타임에 셰이더로 하는 방법도 있지만, 먼저 스크립트로 파일을 뽑는 쪽이 단순합니다.

  </details>

- [ ] 스프라이트 **아틀라스 자동 패킹** 파이프라인

  <details><summary>어떻게</summary>

  1. 폴더의 PNG들을 한 장으로 합치고 좌표를 JSON으로 뽑는 스크립트를 짜세요. 정렬은 높이 내림차순 후 채워넣기(간단한 bin packing)면 충분합니다.
  2. 커밋할 때 자동으로 돌게 하려면 git hook이나 간단한 `make` 타깃으로 걸어두기.
  3. 목적은 성능이 아니라 **손으로 하는 반복 작업 제거**입니다. 스프라이트 하나 추가할 때 손이 안 가야 계속 그리게 됩니다.

  </details>

### 4-2 · 전부 직접 만든 게임 하나

  4. 2~3개월 안에 끝내세요. 늘어지면 안 끝납니다.

  </details>

- [ ] 두 번째 게임잼 — **이번엔 음악까지 직접**

  <details><summary>어떻게</summary>

  1. 잼 시간표에 **음악 3시간**을 미리 넣으세요. 안 넣으면 마지막에 잘려나갑니다.
  2. 3-4에서 만든 곡 중 하나를 **그대로 재활용해도 됩니다.** 잼에서 새로 만들 필요 없습니다.
  3. 1년 전 첫 잼 결과와 나란히 놓고 비교하세요. 이 비교가 이 로드맵의 결과물입니다.

  </details>

- [ ] 작업 과정 글 **1편** 쓰기

  <details><summary>어떻게</summary>

  1. 주제는 **하나만** 고르세요. "픽셀아트 1년 회고"보다 "피격 플래시 셰이더 10줄로 타격감 만들기"가 훨씬 잘 읽힙니다.
  2. 구성: 문제 → 시도한 것 → 안 된 것 → 된 것 → 코드/GIF.
  3. **실패한 시도를 반드시 넣으세요.** 그게 글의 값어치입니다.
  4. 블로그와 GitHub 레포 양쪽에 올리고 서로 링크를 겁니다.

  </details>

- [ ] 1년치 결과물을 **한 페이지로** 정리

  <details><summary>어떻게</summary>

  1. 레포에서 첫 달 폴더와 마지막 달 폴더를 열어, 같은 대상(예: 검)을 그린 것 두 개를 나란히 놓으세요.
  2. 월별 대표작 12개를 격자로 배치한 이미지 한 장을 만들기.
  3. 이 한 장이 어떤 이력서보다 설득력 있습니다. 블로그 글의 대표 이미지로 쓰세요.

## 실패하는 세 가지 방식

거의 모든 중도 포기가 이 셋 중 하나입니다.

**01 · 강의만 보고 안 만든다**
튜토리얼은 이해가 되니까 늘고 있다는 착각을 줍니다. 강의 1개를 봤으면 반드시 결과물 1개를 만드세요. 안 만들었으면 그 강의는 본 게 아닙니다.

**02 · 처음부터 잘하려 한다**
첫 100장은 못 그리는 게 정상입니다. 목표는 잘 그리는 게 아니라 그 100장을 빨리 소진하는 것입니다. 음악도 첫 50곡은 버리는 곡입니다.

**03 · 둘을 동시에 한다**
하루 30분을 그림 15분 + 음악 15분으로 쪼개면 둘 다 안 늡니다. 이 로드맵이 그림 4개월, 음악 4개월로 나눠 놓은 이유입니다.
